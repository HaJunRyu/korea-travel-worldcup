## 1. 한 줄 정의

교통편과 여행 날짜를 알려주면, 전국 여행지 40곳을 **내 조건과 내 여행 시기 기준의
정보**를 보며 1:1 토너먼트로 비교·고민한 끝에 최종 목적지 1곳을 고르는 국내 여행 결정 도구.

## 2. 제품 원칙

1. **게임이 아니라 결정 도구다.** 이상형 월드컵에서 빌리는 것은 토너먼트 '구조'뿐.
2. **고민할 근거를 준다.** 매 매치에서 두 여행지의 명소·음식·가야 할 이유를 나란히 보여준다.
3. **조건이 다르면 정보도 달라야 한다.** 뚜벅이와 자차, 4월과 10월의 같은 여행지는
   다른 여행지다. 접근성·경고·제철·축제·코스는 사용자의 교통편·날짜 기준으로 표시한다.
4. **시간이 걸려도 된다.** 오래 고민해도 좋은 도구. 타이머·재촉 없음, 이어하기 지원.
   (예상 소요시간은 표기하지 않는다 — "30분" 같은 숫자가 오히려 부담을 준다.)
5. **선택은 명시적으로.** 카드 탭 = 정보 열람, 선택은 전용 버튼. 직전 선택 1회 되돌리기.
6. **결과는 계획으로 이어진다.** 우승지 정보 + 내 일정에 맞는 코스 + 시기 정보 + 취향 분석.

## 3. 핵심 설계 결정

### 3.1 대결 단위는 "여행 목적지(도시·지역)"
- 후보는 개별 관광지가 아니라 **강릉·여수·경주 같은 목적지 단위**. 우승 = 행선지 결정.
- 개별 스팟 월드컵은 M4 "심화편"(예: 제주편 — `docs/ideas/jeju-pack.md`)으로 확장.

### 3.1.1 후보 선정 기준 (2026-09-15 명문화)
- 포함: **마음먹고 떠나는 여행 목적지** — 그 지역에 가는 것 자체가 "여행"이 되는 곳.
- 제외: 생활권/도시 단위이거나 반나절 근교 나들이에 가까운 곳.
  → **수도권 중 서울·수원·가평·양평은 제외** (사용자 판단: 여행지로 보기 어려움).
  → **단, 강화도는 여행 목적지로 인정해 포함** (섬 여행 성격).
  제외분 데이터는 `src/data/sudogwon.ts`에 보존 — `src/data/index.ts`에서 전개로 조절.
- 결과: 후보 **40곳** (강원 8 · 충청 6 · 전라 12 · 경상 12 · 제주 1 · 강화도 1).
  국내 여행지는 훨씬 많아서(사용자 지적) 전라·경상을 중심으로 대폭 보강 — 32강 부활.
- 라운드: 40곳이라 **8강·16강·32강 모두 노출** (2^n ≤ 40 → 최대 32강).
  라운드 옵션은 `largestBracketSize(후보수)`로 자동 결정되니, 후보가 늘면 알아서 열림.

### 3.2 접근성 기준 출발지는 MVP에선 "서울/수도권" 고정
- 이동 시간은 (출발지 × 교통수단 × 32곳) 조합이라 출발지를 열면 데이터가 폭발.
- MVP는 수도권 출발 기준으로 표기하고 "서울 출발 기준" 명시. 출발지 선택은 M2+.

### 3.3 시기 정보는 "정적 연례 데이터 → API" 2단계
- 축제·날씨를 처음부터 API로 붙이면 MVP가 무거워짐. 단계적으로:
  - **MVP**: 여행지별 정적 데이터 — 월별 제철 팁(단풍·벚꽃·물놀이 등)과
    연례 축제(매년 비슷한 시기에 열리는 것들)를 월 단위로 매칭
  - **M2**: TourAPI 축제·행사 API로 실제 개최 일정 연동 +
    여행일이 임박(10일 이내)하면 기상청 단기예보로 실제 날씨 표시
- 즉 데이터 구조만 날짜 매칭이 가능하게 잡아두고, 정확도는 단계적으로 올린다.
- **매칭 정밀도와 표현**: MVP는 월 단위 매칭이라 실제 일자와 어긋날 수 있다(9월 말 여행에
  "매년 9~10월" 축제가 걸침). 그래서 문구를 단정적으로 쓰지 않는다 — "여행 기간에 ○○축제"(X)
  → "마침 ○○축제 시즌"(카드), "여행 시기와 겹칠 수 있어요"(상세시트 뱃지). 정확한 일자 매칭은
  M2에서 TourAPI 실일정으로. (사용자 피드백 2026-09-16: 정확 날짜 지정 시 과한 단정은 지양)

## 4. 사용 시나리오

1. 여행 계획 초기 — "10월 24~26일, 뚜벅이" 입력 후 15분 플레이로 행선지 확정
2. 동행자와 취향 맞추기 — 각자 플레이 후 결과·취향 분석 링크 비교
3. SNS 유입 — "내 우승지는 여수 · 나는 바다파" 공유 링크로 유입 → 재플레이

## 5. 게임 규칙

### 5.1 시작 설정
플레이 전 두 가지를 묻는다. 각각 건너뛰기(미정) 가능.

1. **어떻게 이동하세요?** — 🚗 자차·렌터카 / 🚆 대중교통(뚜벅이) / 아직 몰라요
2. **언제 다녀오세요?** — **달력에서 날짜 범위 선택** (시작일~종료일)
   - 빠른 선택 프리셋: 이번 주말 / 다음 주말 / 직접 선택
   - 날짜는 미정이지만 시기는 아는 경우: **월만 선택** 가능 ("10월쯤")
   - 완전 미정: 건너뛰기 → 시기 개인화 없이 일반 정보 표시

날짜에서 파생하는 것:
- **기간(n박 m일)** → 추천 코스 매칭, 당일치기 적합도 경고·소프트 제외
- **시기(월)** → 제철 뱃지("✨ 10월이 절정"), 시즌 팁(단풍·벚꽃·물놀이·기후 경향),
  기간과 겹치는 축제·행사("🎪 여행 기간에 남강유등축제")
- (M2) 공휴일·연휴 감지 → 혼잡·숙소 조기 마감 팁, 임박 시 실제 날씨 예보

설정의 효과 (교통편 포함):
- 카드의 접근성 줄이 내 교통편 기준으로 표시
- 조건과 안 맞는 후보에 경고 뱃지 (뚜벅이 → "⚠️ 현지 렌터카 권장", 당일 → "⚠️ 당일은 빠듯")
- 사실상 불가능한 후보는 소프트 제외 (당일치기 + 울릉도 등, "포함하기" 토글로 복구 가능)
- 시기와 잘 맞는 후보에 제철 뱃지·축제 정보 — **긍정 신호와 경고가 함께 고민 재료가 됨**

### 5.2 토너먼트
- 라운드: **8강 / 16강(기본) / 32강**. 2의 거듭제곱만, 부전승 없음.
- 소요시간은 표기하지 않는다 (제품 원칙 4 참고). 대신 "타이머 없이 천천히" 안내만.
- 대진: (소프트 제외 반영된) 풀에서 무작위 추출 + 셔플.
- 테마 필터(선택): 복수 태그 기반, 해당 테마 8곳 이상일 때만 노출.
- 진행 상태(설정 포함) localStorage 자동 저장 → "이어서 하기".
- 직전 매치 1회 되돌리기(undo).

### 6.1 홈 + 시작 설정 `/`
- 서비스 소개: "고민은 길게, 결정은 확실하게" 톤

### 6.2 플레이 `/play` — 핵심 화면

**모바일 (상하 2카드 + 내부 스크롤)** — 뚜벅이 · 10/24(토)~10/26(월) 설정 예시:

```
┌──────────────────────────────┐
│ 16강 3/8  ▓▓▓░░░  [↩︎ 되돌리기] │
├──────────────────────────────┤
│ ◀ 사진 1/4 ▶     (스와이프)   │
│ 담양   전라 · 자연·미식        │
│ ✨ 10월 말 메타세쿼이아 단풍 절정│
│ "대나무 숲길과 가로수길의 초록"  │
│ 🚆 서울발 KTX+버스 3시간       │
│ 📍 죽녹원·메타세쿼이아길·관방제림│
│ 🍽 떡갈비·대통밥               │
│ [자세히 보기]    [여기로 갈래]  │
├──────────── VS ──────────────┤
│ ◀ 사진 1/4 ▶                 │
│ 순천   🎪 기간 중 순천만갈대축제 │
│ ...                          │
└──────────────────────────────┘
```

- 카드 기본 노출: 사진 캐러셀(3~5장), 지역명, 권역·테마 태그, 가야 할 이유 한 줄,
  **내 교통편 기준 접근성 + 경고 뱃지**, **시기 신호(제철 뱃지 또는 겹치는 축제, 최대 1~2개)**,
  명소 칩 3~4, 음식 칩 2~3
- 정보 위계: 시기 신호(✨/🎪/⚠️)는 한 줄로 제한 — 카드 과밀 방지, 나머지는 상세 시트로
- **[자세히 보기]** 바텀시트: 가야 할 이유 전체, 명소·음식 설명, 시즌 팁 전체
  (내 여행 월 기준 강조), 겹치는 축제 상세, 교통편별 접근성 전체, 현지 이동 난이도,
  적정 일정(내 일정과 비교), 지도 링크
- **[여기로 갈래]** 버튼으로만 선택. 카드 탭은 상세 열람.

**데스크톱**: 좌우 2카드 + 가운데 VS, 카드 내부 스크롤로 상세까지 기본 노출.

**UX 디테일**: 다음 매치 프리로드 / 절제된 선택 애니메이션 / 라운드 전환 화면 / 이미지 폴백

### 6.3 결과 `/result?...`
- 우승 여행지 대형 카드: 사진, 지역명, 권역, tagline, 테마 태그
- **가는 법 (내 교통편 기준)**: 상세 안내 + 현지 이동 팁
- **내 일정 요약 (날짜 기준)**: "10/24(토)~10/26(월) · 2박 3일" + 그 시기 기후 경향 +
  제철 포인트 + 겹치는 축제·행사, (M2) 임박 시 실제 예보
- **추천 코스 (n박 기준)**: 0박→당일 코스, 1박→1박 2일 코스, 2박 이상→1박 2일 코스 +
  "하루 더 있다면" 확장 팁
- 여행 정보: 가야 할 이유, 대표 명소(설명), 대표 음식, 지도 링크
- **우승 여정**: 32강부터 누굴 꺾고 올라왔는지 타임라인
- **취향 분석**: 픽 테마 집계 — "당신의 선택 기준: 바다 60% · 미식 25% · 역사 15%" (클라이언트 계산)
- 준우승 + TOP 4 — "다음 여행 후보로 킵"
- 액션: [다시 하기] [결과 공유하기]
- 공유 복원: `?w=&f=&t=<교통>&from=&to=&picks=<encoded>` — 조건·픽 이력까지 인코딩하면
  코스·시기 정보·취향 분석 포함 복원. 길이 부담 시 축소판(w/f/조건만).
- OG 메타: MVP 정적, M2에서 `@vercel/og` 동적 이미지

## 7. 데이터 기획

### 7.1 모델

```ts
type Theme = '바다' | '자연' | '역사' | '미식' | '감성' | '액티비티';
type Area = '수도권' | '강원' | '충청' | '전라' | '경상' | '제주';
type Transport = 'car' | 'transit';

interface Poi {
  name: string;                // '안목해변 커피거리'
  description: string;         // '해변을 따라 카페가 늘어선 강릉 커피의 성지'
}

interface AccessInfo {         // 모두 서울/수도권 출발 기준 (MVP)
  car: { time: string; note?: string };
  transit: {
    summary: string;           // 'KTX 강릉역 약 2시간' / '비행기 1시간 (김포→제주)'
    quality: '편리' | '보통' | '불편';
  };
  localMobility: '뚜벅이 OK' | '대중교통 보통' | '자차·렌터카 권장';
}

interface SeasonalTip {        // 시기별 팁 — 여행 월과 매칭
  months: number[];            // [10, 11]
  note: string;                // '메타세쿼이아길 단풍 절정, 아침저녁 쌀쌀'
  peak?: boolean;              // true면 카드에 ✨ 제철 뱃지
}

interface Festival {           // 연례 축제·행사 (MVP: 정적, M2: TourAPI 실일정)
  name: string;                // '남강유등축제'
  months: number[];            // [10] — 매칭용
  period: string;              // '매년 10월 초~중순'
  note?: string;
}

interface Course {
  duration: '당일' | '1박 2일';
  plan: string[];              // 동선 요약 3~5줄
}

interface Destination {
  id: string; name: string; area: Area; themes: Theme[];
  tagline: string;
  whyGo: string[];             // 2~3개, [0]이 카드 기본 노출
  highlights: Poi[];           // 3~4곳
  food: Poi[];                 // 2~3개
  seasonalTips: SeasonalTip[]; // 2~4개 (기후 경향 포함, bestSeason을 대체)
  festivals: Festival[];       // 0~3개
  access: AccessInfo;
  tripFit: {
    dayTrip: '가능' | '빠듯' | '불가';   // 서울 기준
    recommendedNights: string;           // '1박 2일 ~ 2박 3일'
  };
  courses: Course[];           // 당일·1박 2일 각 1개
  extendTip?: string;          // '하루 더 있다면 정동진·주문진까지'
  images: string[];            // 3~5장
  kakaoMapUrl: string; naverMapUrl?: string;
}

interface Cup { id: string; title: string; destinations: Destination[]; }
```

- 접근성 줄: transport 기준 car/transit 선택 + localMobility
- 경고 뱃지: 뚜벅이 & 렌터카 권장 / 0박 & dayTrip '빠듯'
- 소프트 제외: 0박 & dayTrip '불가'
- 시기 신호: 여행 월 ∈ seasonalTips.months (peak면 ✨) / 여행 월 ∈ festivals.months (🎪)
- 코스: n박 → courses 매칭, 2박 이상은 1박 2일 + extendTip

### 7.2 콘텐츠 제작 계획

- 분량: 40곳 × (이유 2~3 + 명소 3~4 + 음식 2~3 + 접근성 3종 + 시즌 팁 2~4 + 축제 0~3 +
  코스 2 + 확장 팁) ≈ **600개 문장 규모**. M1의 최대 작업.
- 초안은 AI로 일괄 작성 후 검수. **사실 확인 우선순위: ① 접근성(KTX 노선·소요시간·현지 이동)
  ② 축제의 개최 시기(연례 기준) ③ 코스 동선 현실성**. 시간은 "약 ~시간", 축제는
  "매년 ~월" 수준으로 표기해 오차 흡수. 정확한 일정·날씨는 M2에서 API로.
- 문체: 광고가 아니라 **친구가 추천해주는 톤**, 구체적 경험 중심.

### 7.4 이미지·정보 출처

**이미지: Wikimedia Commons 실사진 채택 (2026-09-15 확정·적용).**
- 각 여행지의 랜드마크 영문명(예: "Bulguksa", "Suncheon Bay Wetland")으로 검색해
  대표 사진 1~3장씩 수집 → **40곳 전부, 총 98장**. 수집 스크립트: `scratchpad/collect_photos.py`
  (증분 저장·이어하기·배치 제한; Wikimedia rate limit 때문에 delay 1.2s + 배치 8곳씩).
- 결과는 `src/data/photos.generated.ts` (url·credit·descUrl). `index.ts`의 `withRealPhotos`가
  placeholder를 실사진으로 대체(없으면 placeholder 유지). 저작자·라이선스 `credit`은
  **결과 화면·상세시트에 표기** (CC 라이선스 준수).
- 호스트: 썸네일 `thumb.wikimedia.org` + 원본 `upload.wikimedia.org` 둘 다 `next.config` 허용.
- 로딩 최적화: `next/image` AVIF/WebP 변환 + 30일 캐시(`minimumCacheTTL`) + Wikimedia CDN.
  picsum(랜덤 생성이라 느림) 대비 근본 개선.
  - **카드 캐러셀**: 한 여행지의 사진을 모두 겹쳐 미리 로드(첫 장 priority, 나머지 eager)하고
    opacity로 전환 → 넘김이 즉각 반응. 로딩 중엔 공통 blur placeholder(`BLUR_FALLBACK`).
  - 이미지별 실제 blur(16~120px base64)는 만들어봤으나 클라이언트 번들을 400KB+ 키워
    초기 로딩에 역효과라 **공통 placeholder로 대체** (이미지별은 CDN 분리 등 후속 과제).
  - 카드 상단 태그(권역·테마): 밝은 사진에서도 읽히도록 상단 dim 스크림(`SCRIM_TOP`) +
    어두운 태그 배경(`blackAlpha.600`).
  - **깨짐 방지(중요)**: `upload.wikimedia.org` **원본 직접 URL은 Wikimedia가 429로 차단**해
    next/image 최적화 시 깨진다. 반드시 **thumb 경로(`/thumb/`, thumb.wikimedia.org 등) URL만**
    사용한다 — `scripts/collect_photos.py`가 검색 결과 중 thumb URL이 나오는 것만 채택하도록
    복원해둠. 저해상도라 썸네일이 없는 사진은 버린다. (2026-09-16 전수 점검: 95장 0 깨짐)

미결/개선 여지:
- 자동 수집이라 일부 사진 정확도 편차 가능 → 배포 전 육안 검수, 부정확분은 파일에서 직접 교체.
- 더 공식적 사진이 필요하면 한국관광공사 TourAPI(공공누리, 키 발급 필요)로 보강 가능.
- 축제 실일정·날씨는 여전히 M2에서 TourAPI·기상청 API로 (7.3, 3.3 참고).

### 8.3 게임 상태 설계

```ts
interface TripSettings {
  transport: Transport | null;   // null = 미정
  startDate: string | null;      // ISO 'YYYY-MM-DD'
  endDate: string | null;
  month: number | null;          // 날짜 미정, 월만 아는 경우
  includeExcluded: boolean;      // 소프트 제외 해제
}
// 파생값: nights = endDate - startDate, months = 여행이 걸치는 월 목록 (또는 [month])

interface Pick { winnerId: string; loserId: string; round: number; }

interface GameState {
  settings: TripSettings;
  round: number;                 // 16 → 8 → 4 → 2
  entrants: Destination[];
  matchIndex: number;
  winners: Destination[];
  picks: Pick[];                 // undo·취향 분석·우승 여정의 근거
  finished: boolean;
}
// 액션: START(pool, size, settings) / PICK(winnerId) / UNDO
```

## 9. 통계 설계 (M3)

- `POST /api/results` — `{ cupId, winnerId, finalistId, picks, settings }` 전송
- 집계: 여행지별 승률·우승 + **조건별·시기별 랭킹** ("뚜벅이 1위", "10월 여행자의 1위",
  "당일치기 1위") — settings·날짜를 받기에 가능해지는 콘텐츠
- 어뷰징은 초기엔 무시, 필요 시 IP rate limit

## 11. 미결 사항

1. **날짜 입력 범위** — 과거 날짜 차단, 최대 기간(예: 14박 상한?) 등 입력 제약.
2. **축제 데이터 범위(MVP)** — 여행지당 대표 연례 축제 0~3개만 수집하는 안으로 충분한지.
3. **출발지 서울 고정(MVP)** — 3.2 결정대로 갈지. 출발지 선택은 M2.
4. **서비스명** — 후보: 여행컵, 트립픽(TripPick), 어디갈컵, 국내여행 월드컵.
5. **이미지 소스** — 7.4 권장안대로 갈지.
6. **후보 검수** — 수도권은 강화도만 포함, 전라·경상 보강으로 40곳(2026-09-15). 그 외 넣고 빼고 싶은 지역 검토.
